# Правила командной работы

## Основная ветка
Основная ветка проекта — `main`. Напрямую в `main` не коммитим: изменения вносятся в тематических ветках и принимаются через Pull Request.

## Именование веток
Используйте понятные префиксы:
- `docs/краткое-описание` — документация;
- `uml/краткое-описание` — диаграммы;
- `feature/краткое-описание` — функциональность;
- `fix/краткое-описание` — исправления.

## Коммиты
Сообщение должно кратко описывать конкретное изменение, например: `Добавлен сценарий UC-03` или `Обновлена навигация docs README`. Не используйте сообщения вроде «изменения» или «финал».

## Pull Request
В описании укажите:
1. цель изменения и связанную задачу;
2. связанные ФТ и UC, если применимо;
3. изменённые файлы;
4. способ проверки;
5. известные ограничения.

Автор не подтверждает собственную работу вместо проверяющего. Проверяющий перечисляет проверенные материалы и замечания либо объясняет, почему изменение согласовано. После исправления замечаний выполняется слияние в `main`.

## Актуальность документации
Markdown — рабочая редактируемая версия отчётов. После согласования и перед сдачей обновляется Word-версия. Исходник диаграммы (`.puml`/`.drawio`) и соответствующее изображение обновляются вместе. Если содержательная правка сделана сначала в DOCX, её необходимо перенести в Markdown.

## Безопасность
Не добавляйте в репозиторий пароли, токены, приватные ключи и реальные секреты. Используйте `.env.example` без секретных значений.
